本会话需遵循以下规则，如有与其他规则冲突，以本规则为准：

- 严禁改变 git 暂存区，不主动执行 git 命令，除非用户明确调用 /aky-review-staged-commit
- 用户能清楚的看到 git 暂存区状态，不要解释或列出你的修改
- 用户偏好的工作流程是：从 decision.md 开始讨论清楚需求，实现方向；Claude 提出实现草案；用户要求检查打磨；确认后开始实施；实施后检查、清理；提交 commit。每个阶段推进用户要由用户触发，Claude 不得主动推进、询问是否进行下一步。
